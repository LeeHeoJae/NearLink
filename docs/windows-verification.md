# Windows 초기 구현 검증 · 2026-11-13

## 구현 범위

Rust + Win32로 만든 수신 전용 트레이 앱입니다. 기기 검색, OS 페어링 요청, 암호화 GATT,
NearLink 세션 검증, 배터리·충전 상태 알림 수신, 재연결, 별명, 부족·완충 알림,
사용자 선택에 따른 로그인 자동 시작과 수신 중지 상태 저장을 구현했습니다.
Android는 명령 5로 등록된 PC에 대해 역방향 배터리 연결을 생성하지 않습니다.

## 빌드와 자동 검사

- Windows: `cargo test --locked`의 테스트 6개 성공.
- `cargo clippy --all-targets --locked -- -D warnings` 성공.
- `cargo build --release --locked` 성공. x64 실행 파일 **433,152바이트(423KiB)**.
- PE 의존성 검사에서 Windows OS DLL만 확인했습니다. WebView, .NET 또는 별도 VC 런타임 DLL에 의존하지 않습니다.
- Android: `assembleDebug`, `testDebugUnitTest`, `lintDebug` 성공. 단위 테스트 **32개**, 실패 0개.
- 새 제어 명령의 인증·준비 조건, 송신 전용 상태의 설정 완료 판단을 Android 테스트에 추가했습니다.
- Windows 테스트는 Android와의 패킷 호환, 잘못된 배터리/세션 데이터 거부, 설정 교체 저장,
  중지 상태 복원, 알림 중복 억제·재활성화, 준비 전 알림 억제와 중지 후 지연 데이터 무시를 검증합니다.

## 화면 및 동작 확인

실제 Windows 데스크톱에서 별도 검증 프로필로 실행했습니다. Windows 기본 컨트롤의
기기 목록 중심 구성, 시스템 글꼴, 별도 검색·설정 창이라는 화면 계약으로 검사했습니다.

- 빈 목록 안내, 기기 미선택 시 비활성 동작, 설정 창과 저장 후 닫기를 확인했습니다.
- 빈 목록 안내가 목록 컨트롤에 가려지는 문제를 발견해 네이티브 빈 목록 마크업으로 수정했습니다.
- 설정 창의 포커스 처리를 보완하고, 검색·설정 창은 소유 창으로 유지하면서 주 창도 활성 상태로 두었습니다.
- 실제 Android NearLink BLE 광고 한 건을 발견했고 기기 이름을 표시했습니다.
- 15초 검색 종료와 이후 재검색 버튼 활성화를 확인했습니다. 발견한 기기에 연결·페어링을 시도하지는 않았습니다.
- 관리 창을 닫았을 때 창이 사라지고 프로세스가 트레이에서 유지되는 것을 확인했습니다.
- 실제 화면은 기본 배율에서 검사했습니다. 다른 DPI 배율과 여러 모니터 간 이동은 추가 검증 대상입니다.

## 자원 측정

BLE 광고 검색 후 관리 창을 닫고, **등록/연결 기기 0대**인 검증 인스턴스에서 측정했습니다.
시스템 공유 코드 페이지를 포함하는 작업 집합과 전용 메모리를 구분합니다.

| 항목 | 측정값 |
| --- | ---: |
| 작업 집합 | 29,818,880바이트 · 약 28.4MiB |
| 전용 메모리(Private Bytes) | 4,161,536바이트 · 약 4.0MiB |
| 10.1초 동안 CPU 사용 시간 증가 | 0.0초 |
| 스레드 | 7개 |

검증 중 사용한 빌드는 위 최종 실행 파일과 크기가 같고, 이후 암호화 보호 수준 명시 및
중지 후 지연 데이터 무시를 추가했습니다. 이 수치는 연결 중 메모리나 장시간 CPU·전력 사용량을
보장하지 않습니다. Windows BLE/COM 라이브러리 로딩과 연결 기기 수에 따라 달라질 수 있습니다.

## 아직 검증하지 않은 항목

- 새 Android APK와의 페어링·JOIN_RECEIVER·HELLO/READY/ACK 및 실제 배터리 변경 수신.
- Android↔Android 기존 연결과 PC 연결을 동시에 사용하는 실기기 동작.
- 알림의 실제 Windows 표시, 로그인 자동 시작, PC 절전·재부팅·블루투스 재시작 후 복구.
- 다중 기기 장시간 안정성, 수신 중 CPU·메모리·배터리 소모, Windows 10·ARM64 실행.
- 삼성 기본 배터리 위젯의 PC 표시나 이름 변경. 이번 Windows 앱은 PC 배터리를 송신하지 않습니다.

연결 시험에는 이 변경이 포함된 Android APK가 필요합니다. 이전 Android 버전에서 명령 5를
거부하면 양방향 연결 명령으로 우회하지 않습니다. 사용 절차는 [Windows README](../windows/README.md)를 참고합니다.
