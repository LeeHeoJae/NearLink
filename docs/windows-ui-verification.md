# Windows 11 UI 개선 검증 · 2026-11-13

## 구현

Rust + Win32를 유지하고 표를 기기별 세로 목록으로 바꿨습니다. 이름, 잔량·충전 상태,
연결 상태, 마지막 수신을 표시하며 기존 기기 추가, 별명, 알림, 자동 시작과 수신 중지를 유지합니다.
트레이 왼쪽 클릭은 작은 빠른 보기를 열고, 오른쪽 클릭은 Windows 기본 메뉴를 사용합니다.

Android NearLink의 파란색과 문구를 이어가면서 시스템 제목 표시줄, 기본 메뉴와
네이티브 목록·버튼의 접근성 정보를 유지합니다. 앱 테마, 고대비와 텍스트 크기를 읽고
창을 모니터 작업 영역에 맞춥니다. 큰 글자로 공간이 부족하면 기기 동작을 메뉴로 제공합니다.
연결 끊김, 수신 중지와 오래된 값은 문구로 구분합니다. 15분 이상 갱신되지 않은 값은
연결 유지 여부와 별개로 오래된 값으로 표시합니다.

## 확인한 범위

- Windows에서 밝은·어두운 목록 화면, 선택, 별명 변경, 수신 중지와 다시 연결을 확인했습니다.
- 기기 추가 창, 설정 창과 저장 후 관리 화면 복귀를 확인했습니다.
- 목록 항목의 전체 상태 문구가 Windows 접근성 트리에 노출되는 것을 확인했습니다.
- 예시 데이터로 150% 글자 확대 화면과 고대비 팔레트를 확인했습니다.
- `--quick-view`로 빠른 보기의 실제 창과 예시 기기 네 대의 표시를 확인했습니다.
- 일반 프로필의 빈 목록 안내와 어두운 화면의 대비를 확인했습니다.
- 최종 소스의 release 빌드, Clippy 검사와 단위 테스트 7개가 통과했습니다.
  공간 부족 시 동작 메뉴 배치는 화면 검증이 남아 있습니다.

미리 보기는 별도 `--data-dir`를 요구하며 예시임을 표시합니다. BLE, 배터리 알림,
설정 저장과 자동 시작 변경을 실행하지 않습니다. 화면 산출물은 Git에서 제외하는
`ui-review/windows/`에 저장했습니다.

## 실행 파일과 자원

동일한 release 설정으로 이번 UI 변경 직전 작업 트리의 빌드와 비교했습니다.
버전 번호만으로 구분한 배포 버전 간 비교는 아닙니다.

| 항목 | 변경 전 | 변경 후 |
| --- | ---: | ---: |
| x64 실행 파일 | 433,152바이트 · 423KiB | 456,192바이트 · 445.5KiB |

22.5KiB, 약 5.3% 증가했습니다. 별도 런타임이나 브라우저 엔진은 추가하지 않았습니다.
PE 의존성 검사에서는 Windows 제공 DLL만 확인했습니다. UI 변경으로 DWM API를 사용합니다.

등록 기기 0대인 두 검증 프로필을 실행하고 관리 창을 닫는 것까지 진행했으나,
최종 빌드의 유휴 메모리와 CPU 비교 측정은 완료하지 못했습니다. 이전 구현의 측정치는
[초기 검증 기록](windows-verification.md)에 있으며 이번 변경 후 수치로 해석하면 안 됩니다.

## 남은 검증

사용자가 물리적 Esc 키로 Computer Use를 중지해 화면 검증을 종료했습니다.

- 225% 글자 크기에서 공간 부족 시 동작 메뉴 배치.
- 트레이 아이콘의 실제 마우스 클릭과 빠른 보기 버튼을 통한 기기 추가·설정 이동.
  자동화 도구가 소유 창에 포커스를 옮기면서 빠른 보기가 닫혀 클릭 결과를 확인하지 못했습니다.
- 실제 Windows 고대비 설정 전환, 여러 DPI 모니터 간 이동, 스크린 리더 낭독.
  고대비와 글자 확대 화면은 미리 보기 설정으로 확인했습니다.
- 실제 BLE 페어링·배터리 변경 수신, Windows 알림 표시, 로그인 자동 시작,
  절전·블루투스 재시작 복구와 다중 기기 장시간 동작.
- 동일한 조건에서 최종 빌드의 유휴 메모리·CPU 측정.

시스템 제목 표시줄, 메뉴, 스크롤 막대와 메시지 상자는 Windows 표준 표시를 유지합니다.
UI 기준은 [Windows 디자인 문서](../windows/DESIGN.md)에 기록했습니다.
